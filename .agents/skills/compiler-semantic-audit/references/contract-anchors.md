# Contract/source anchors
Researched 2026-10-13. These anchors demonstrate where to investigate, not a completed certification of the projects' semantics.

## CubeCL
- [FastMath](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/properties.rs) defines `NotNaN`, `NotInf`, `UnsignedZero`, `AllowReciprocal`, `AllowContraction`, `AllowReassociation`, `AllowTransform`, `ReducedPrecision`. Comments specify some assumptions/relaxations. Locate actual frontend defaults and attribute propagation rather than treating enum existence as enforcement.
- [InstructionModes::fp_math_mode](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/scope.rs) holds expansion modes. Follow operation construction and clone/fusion/lowering paths to establish what a particular operation carries.
- [math definitions](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/dialect/math.rs) contains `const_eval!` and `simplify!` implementations. At the snapshot, `FAddOp` has zero-add simplifications; `FSubOp` has a scalar self-subtraction fold. These are implementation evidence, not an explicit comprehensive contract. Follow macro definitions and caller checks; do not assume a mode check from a pattern's name.
- [SimplifyOps](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/rewrite.rs) invokes `SimplifyInterface::check_fold`; [InstCombine](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-opt/src/passes/inst_combine.rs) forms FMA from a lone product plus add/sub. The latter's existence is not proof contraction is always semantically permitted.
- Follow [generate_simplify](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-macros-internal/src/generate/simplify.rs) and [SimplifyInterface](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/interfaces/mod.rs) when closing a hidden-gate question. At this snapshot the FAddOp zero pattern, generated check_fold implementation and SimplifyOps caller do not test a FastMath zero-sign/NaN mode. This locates implementation behavior without supplying a comprehensive frontend contract.
- [ToLLVMDialect math](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-llvm/src/shared/to_llvm/math.rs) maps operations into LLVM dialect ops. At the snapshot, add/sub/mul use target-dependent contraction handling, while division/remainder use a no-fast-math helper. Keep this evidence separate from frontend modes and contract.
- [comparison/extrema dialect](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/dialect/cmp.rs) distinguishes ordinary and NaN-propagating extrema operations. [binary runtime tests](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-core/src/runtime_tests/binary.rs) includes signed remainder and math/extrema cases; [atomic tests](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-core/src/runtime_tests/atomic.rs) supports memory investigation. Inspect exact asserted cases and target registration.
- [atomic IR definitions](https://github.com/tracel-ai/cubecl/blob/3b47011522dbe79544388267c2b6cf8278913a8b/crates/cubecl-ir/src/dialect/atomic.rs) is an entry point, not a complete memory model.
- Historical change [08c2b16](https://github.com/tracel-ai/cubecl/commit/08c2b16eaab030f64b71bd54bb3ebc3d1329eb12) corrects signed remainder and adds NaN-propagating extrema, with runtime tests and target lowerings. Use it as scoped intent evidence; never generalize it to all floating-point operations.
- Do not confuse `cubecl-std/src/fast_math.rs`, which implements integer `FastDivmod`, with the floating-point `FastMath` contract.

## Other layers
- PyTorch: establish API semantics and dtype/promotion behavior for the exact overload from official documentation and tests; inspect [pointwise lowering](https://github.com/pytorch/pytorch/blob/60de3b7f3316d28ab80fb8029742e201d5c6ab7b/torch/_inductor/lowering.py) for implementation choices, not as sole API specification.
- Burn: [CubeBackend](https://github.com/tracel-ai/burn/blob/f7de05ffc17b04bf718c2b2a51e1f415548d32e0/crates/burn-cubecl/src/lib.rs) is a framework consumer of CubeCL. Its tensor contract and fusion choices must be established independently; using the same kernels does not make PyTorch and Burn equivalent.
- Pliron: [DialectConversion](https://github.com/pliron-org/pliron/blob/d7ec90818cc9793452f62f91df906e9329722198/src/irbuild/dialect_conversion.rs) provides conversion infrastructure; [PMConfig](https://github.com/pliron-org/pliron/blob/d7ec90818cc9793452f62f91df906e9329722198/src/pass.rs) supports structural verification. CubeCL operation semantics remain the dialect author's responsibility; a Pliron LLVM dialect is not automatically native LLVM IR.
- LLVM: use the [version-matched Language Reference](https://llvm.org/docs/LangRef.html), including fast-math flags, instruction/intrinsic definitions, poison/undef, conversions, atomics and memory model. Map the exact operation/flags; names such as remainder or min/max are insufficient. The web page may be newer than the vendored LLVM.
- NVIDIA: [PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html), [NVRTC options](https://docs.nvidia.com/cuda/nvrtc/index.html), [CUDA compiler options](https://docs.nvidia.com/cuda/cuda-compiler-driver-nvcc/index.html) specify separate target/compiler layers. Trace modifiers and actual tool options; GPU generation support can restrict valid instructions.
- AMD/HIP: derive behavior from current selected CubeCL lowering plus official ROCm/LLVM AMDGPU documentation for the installed compiler/device. Do not translate PTX modifiers or NVIDIA exception/subnormal rules by name.

No global IEEE-strict CubeCL contract was established by this bounded research. The skill therefore requires an explicit contract investigation before a validity verdict; that is an evidence gap, not an assertion that semantics are absent.
