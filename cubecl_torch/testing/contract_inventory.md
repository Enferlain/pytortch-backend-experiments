# Historical gate contract inventory

Generated by `python -m cubecl_torch.testing.contract_inventory`; do not edit by hand.

Every assertion site in the frozen Stage 0-5 gate scripts (as enumerated by
`gate_assertions.py`) is either a **live** contract, ported to the linked package
test under `cubecl_torch/testing/`, or **historical**, with the reason below.

## Historical reasons

- **H-BACKEND**: Drives a superseded Stage 1-3 backend entry point with its own capability set, wire schema and runtime. The live front end is the Stage 4/5 chain; its behaviour on these semantics is covered by the 168-case Stage 5 corpus (equivalent to Stage 5 at the consolidation, guarded since by the manifest, testing/manifest_check.py) and the linked live contracts.
- **H-ABI**: Checks a superseded per-stage native entry or Python wrapper (stage0_launch..stage4_launch, Stage 0 Kernel._enqueue, Stage 2 prepare(), Stage 3 ReductionPlan). The live runtime has one contract-driven launch path.
- **H-COUNTERS**: Cross-checks per-stage native counters (Stage 3/4 launch and shared-byte counters) against per-stage Python counters: bookkeeping of the superseded runtimes. Launch-count parity for the live runtime is covered by test_contracts_runtime.py::test_trace_scopes_and_counters.
- **H-LLVM**: LLVM route: an offline comparison compiler route, not the production C++/NVRTC route.
- **H-CAPTURE**: CUDA graph capture through the Stage 0 ABI. Every later stage and the live runtime refuse capture (test_contracts_runtime.py::test_capture_refused).
- **H-HARNESS**: Script-level aggregation or precondition (exit status after failures, dynamo error suppression off); not a behaviour contract.
- **H-EVIDENCE**: Profiler naming evidence for a one-off audit kernel; generated kernel census for the live path is covered by test_contracts_effects.py::test_profiler_census_generated_kernels_only.
- **H-STAGE1-PLAN**: Stage 1 schema-1 wire plan (bridge_description); schema 1 is not produced or accepted by the live compiler.
